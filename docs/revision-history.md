# Firmware Revision History

Server revision history lives in the [server repo](https://github.com/vcchstrandberg/netatmo-home-hub/blob/main/docs/revision-history.md).

| Version | Date | Notes |
|---|---|---|
| v2.15 | 2026-08-06 | **OTA rolled out fleet-wide** (all ESP32 targets: `esp32c6_waveshare_lcd`, `esp32c6_zero_ili9341`, `esp32c6_zero`, `esp32cam`, `esp32dev` — `esp32s3_waveshare_lcd` already had it). `OTA_ENV_NAME`, defined per board in the platform-selection block, now drives whether `ArduinoOTA`/`Update`/`Preferences`/NTP code compiles in and what `/firmware/<env>/...` URL Phase 2 uses — generalized from the S3-only code in v2.9–v2.14. New `esp32c6_waveshare_lcd_ota` / `esp32c6_zero_ili9341_ota` / `esp32c6_zero_ota` / `esp32cam_ota` / `esp32dev_ota` PlatformIO envs (Phase 1 push), same `extends`-a-separate-env pattern as the S3 one. Boot splash on both LVGL boards and the ILI9341 TftUI board gained the update-timestamp/method line (their `showBootSplash()` signatures extended to match); the three 128×64 OLED boards get the info via Serial only — no room for a 5th splash line at that resolution. Phase 0 work along the way: (1) discovered `esp32cam` was never actually OTA-safe despite no partition override — decoding its real build output found a single 3MB slot, not the two-slot `default.csv` `esp32dev` genuinely gets from the same "no override" starting point; fixed. (2) `esp32c6_zero`'s existing 1.25MB `default.csv` slots hit 95.3% full once OTA code was added — widened it and the two other small-slot boards to `ota_nofs_4MB.csv` (1.9375MB slots). (3) New `partitions_c6_8mb_ota.csv` (repo root) for the two 8MB C6 boards on `huge_app.csv` — no built-in scheme fits an 8MB chip with two ~3MB slots. Both C6 boards' physical flash sizes confirmed via `esptool flash-id` directly on hardware, not assumed from spec pages (`esp32cam`/`esp32dev` weren't connected, so their 4MB assumption is unverified — safe regardless, since a 4MB-total table fits even a larger real chip). Verified end-to-end on `esp32c6_waveshare_lcd` and `esp32c6_zero` (USB flash, clean boot, no loop); `esp32c6_zero_ili9341`/`esp32cam`/`esp32dev` are ready in code but not yet flashed (not connected this session). |
| v2.14 | 2026-08-06 | **Suppress harmless `Preferences` `NOT_FOUND` log noise** (`esp32s3_waveshare_lcd`) — `Preferences::remove()` logs an `ESP_LOGE` line for an absent key, which happens on every ordinary boot now that `pendingOta` is consumed unconditionally (v2.13). Guarded with `isKey()` first. Cosmetic only. |
| v2.13 | 2026-08-06 | **Fix stale `pendingOta` flag surviving across USB flashes** (`esp32s3_waveshare_lcd`) — `recordFirmwareUpdateInfo()` only read/cleared the flag inside the "version actually changed" branch. USB flashing doesn't touch NVS, so a flag left set by an earlier OTA event not immediately followed by a boot that reached this code could survive across later USB flashes and mis-attribute an unrelated USB update as OTA — observed directly during testing. Fixed by consuming the flag unconditionally on every boot. |
| v2.12 | 2026-08-06 | **Log the recorded update timestamp/method to Serial** (`esp32s3_waveshare_lcd`) — small diagnostic addition alongside v2.11's boot-splash line, so it's checkable without needing eyes on the LCD. |
| v2.11 | 2026-08-06 | **OTA Phase 2 hardening + update provenance + server-visible device versions** (`esp32s3_waveshare_lcd` only, except the last item). Fixes a real reboot-loop incident from the same day's live verification (see `docs/production-readiness.md` for the full account): `checkForFirmwareUpdate()` now persists the last-attempted server version string in NVS and skips a repeat of the exact same offer instead of retrying forever, and the boot-time check moved to run after WiFi connects (was blind at the very start of `setup()`, before the dashboard ever rendered). Also: the boot splash gained a 5th line showing when this firmware was last updated and by what method (`OTA` vs `USB`) — method comes from an NVS flag set just before any OTA-triggered reboot (absent ⇒ USB, since esptool has no code path to set anything), timestamp from NTP (`pool.ntp.org`, UTC, best-effort). Separately, **every** board (not just S3) now sends `X-Device-Firmware: <APP_VERSION>` on `/weather` requests; paired with server v1.20's new `fw_version` device-list column. |
| v2.10 | 2026-08-06 | **OTA Phase 2 — device-side pull update via the proxy** (`esp32s3_waveshare_lcd` only). `checkForFirmwareUpdate()`: `GET /firmware/esp32s3_waveshare_lcd/version` from the proxy, compare against `APP_VERSION`, and on a mismatch `GET .../bin` and flash it via `Update`, then `ESP.restart()`. Runs once on boot and every 24 h from `loop()`. The server half (two new proxy routes) lives in `netatmo-home-hub`. (The boot-time call shipped here had the reboot-loop bug fixed in v2.11 — see that entry.) |
| v2.9 | 2026-08-06 | **OTA Phase 1 verified end-to-end** (`esp32s3_waveshare_lcd` only) — `ArduinoOTA` added (listener starts after WiFi connects, hostname = `DEVICE_NAME`, IP logged to Serial), pumped in `loop()`. `upload_protocol = espota` lives on a separate `esp32s3_waveshare_lcd_ota` PlatformIO env (via `extends = env:esp32s3_waveshare_lcd`) so plain `--target upload` keeps defaulting to USB. Verified on real hardware: USB-flashed once to install the listener, then pushed the same build again over WiFi and confirmed the device rebooted and reconnected normally. Unauthenticated — same trusted home LAN only. |
| v2.8 | 2026-08-06 | **OTA Phase 0 — two-slot partition table** (`esp32s3_waveshare_lcd` only). Investigation found `huge_app.csv` (used by all three Waveshare LVGL/TFT targets) has an `otadata` partition but only one `app0` slot — no A/B rollback safety despite `otadata` being present. Migrated this target to the stock `default_16MB.csv` scheme (two 6.25 MB app slots), sized for its real 16 MB chip (current binary was 1.35 MB — enormous headroom). Confirmed via a full upload that PlatformIO rewrites bootloader + partition table + app on every `--target upload`, not just the app region. The two C6 boards on `huge_app.csv` still need a custom two-slot table (no off-the-shelf scheme fits their 8 MB chip cleanly) — not done here. See `docs/production-readiness.md` for the full OTA roadmap. |
| v2.7 | 2026-08-05 | **New target `esp32s3_waveshare_lcd`** — Waveshare ESP32-S3-LCD-2.8 (the non-touch variant; "ESP32-S3-Touch-LCD-2.8" is a different board). Built as a sibling to the C6 Touch LCD target, reusing the LVGL + Arduino_GFX + QMI8658-orientation architecture, but adapted for real differences confirmed against the official demo firmware and real hardware: (1) **stock ST7789** panel (240×320, no col/row offset) — Arduino_GFX's built-in init is used as-is, unlike the C6's JD9853 which needs a custom register sequence; (2) **no touch controller at all**. A first cut repurposed the board's second physical button ("PWR_KEY", GPIO6) as a page-advance stand-in for a touch swipe, mirroring the C6's 3-page carousel — rejected after testing on real hardware ("the device has no way of shifting screens"), so the final design drops paging entirely: `src/lvgl_ui_s3.cpp` lays out indoor, outdoor, rain, and tomorrow's forecast **all at once** in a single 2×2 grid, sized from the panel's actual width/height rather than hardcoded, using the ~40% more screen area this panel has over the C6's 172×320. There is no About page (it only existed as a third swipeable page on the C6, and there's no navigation path to reach it here). (3) **Orientation mapping required a board-specific fix** — this board's QMI8658 is mounted rotated 90° relative to the C6's, so `rotationFromAccel()` in `src/orientation.cpp` swaps the X/Y axis roles under `WAVESHARE_ESP32S3_LCD` (confirmed against real hardware: portrait matched immediately after the axis swap, landscape needed one further sign flip). Locale cycling reuses the existing generic BOOT-button (GPIO0) short-press handling in `main.cpp` unchanged. Scope matches the C6 board — the official demo's RTC, SD card, and audio DAC are not wired up. |

| v2.1 | 2026-06-07 | **High-pressure sun icon on both C6 TFT targets.** The outdoor section now shows a small golden sun when the barometric pressure is high (raw reading ≥ 1020 hPa, shared `HIGH_PRESSURE_HPA` constant). The threshold is compared against the raw hPa value, not the displayed number, so it triggers identically whether the locale shows hPa or inHg. On the **Waveshare LCD** it's drawn from LVGL primitives (a filled disc plus eight `lv_line` rays) in the bottom-right of the outdoor card, created once per layout build so it survives orientation rebuilds. On the **ESP32-C6-Zero ILI9341** it's drawn with LovyanGFX (filled disc plus eight `drawWideLine` rays) in the open space to the right of the outdoor temperature, anchored to the measured text width so it clears the unit glyph. The Montserrat/GLCD fonts have no sun glyph, hence the hand-drawn primitives. `LvglUI::setOutdoor()` and `TftUI::drawDashboard()` each gained a `bool highPressure` parameter. OLED targets are untouched. |
| v2.0 | 2026-06-01 | **New target `esp32c6_zero_ili9341` + Uno R4 LED-matrix WiFi indicator.** (1) The Waveshare ESP32-C6-Zero driving an external generic 2.4″ ILI9341 240×320 SPI TFT. TFT_eSPI does not compile for the ESP32-C6 (GPIO register incompatibility), so rendering uses **LovyanGFX** in a new `TftUI` namespace (`src/tft_ui.cpp`), guarded by `ESP32C6_ZERO_TFT`. This red clone needs `rgb_order=true`, `invert=false`, and an all-rotation boot wipe to clear a GRAM-offset strip its flipped rotations leave behind. Orientation is a build flag (`-DTFT_ROTATION`, default `5` = portrait); landscape was dropped because the clone misreports per-rotation dimensions and there's no accelerometer to auto-rotate. Pins SCLK18/MOSI19/MISO20/DC4/CS5/RST3, 3.3 V only, `huge_app.csv` partitions. Full-dashboard layout (no card cycling), three stacked sections. (2) **Uno R4 WiFi LED matrix** — the onboard 12×8 matrix shows a happy face when WiFi is connected, sad when not (sad on boot until the join completes; flips automatically in `loop()` on link change). Guarded by `HAS_LED_MATRIX` so other targets are untouched. The matrix is monochrome red, so the smile/frown shape is the only signal. |
| v1.9 | 2026-05-28 | **Uno R4 MAC identity fix** — the Uno R4 WiFi path used `WiFi.macAddress()` with no argument (ESP32-style, returning a `String`), but the Uno's `WiFiS3` library only offers `macAddress(uint8_t*)`. That meant the `uno_r4_wifi` target **failed to compile since v1.6**, so the deployed Uno was still running pre-v1.6 firmware that sends no `X-Device-Id` — and the hub listed it as a `web` client rather than a device. Fixed by filling a `uint8_t[6]` buffer and formatting it with `snprintf` into the same `AA:BB:…` form the ESP32 path sends. The ESP32 targets were never affected (their WiFi lib has the `String` overload). Reflash the Uno to pick up its identity; the stale `unknown-<ip>` row can be removed in the hub UI. |
| v1.8 | 2026-05-28 | **C6 Touch LCD: backlight dimming** — the backlight (GPIO23) moved from a plain digital on to LEDC PWM, exposed as `LvglUI::setBacklight(percent)`. `parseWeather()` reads an optional `backlight` (0–100) field from `/weather` and applies it; absent on older hubs, in which case brightness is left untouched. The hub owns all the policy (time-of-day ramp from the station's sunrise/sunset) — the device just applies the number it's handed. Paired with server v1.14. |
| v1.7 | 2026-05-27 | **New target: Waveshare ESP32-C6-Zero** — bare ESP32-C6 board with an external SSD1306 OLED. The C6-Zero doesn't break out the ESP32-C6 Arduino variant's default I2C pins (GPIO 22/23), so the firmware calls `Wire.begin(6, 7)` explicitly to land on pins Waveshare does expose (the variant's `Wire1` defaults). Reuses the U8g2/SSD1306 code path from `esp32dev` and the pioarduino C6 platform from the Touch LCD target; new `ESP32C6_ZERO` build flag branches `main.cpp` to set `BUTTON_PIN=9` (the C6 BOOT pin). USB-CDC build flags route `Serial` over the USB-Serial-JTAG bridge so the boot log is visible without a separate UART adapter. Verified on hardware (boot, WiFi associate, `GET /weather` all succeed prior to wiring up a display). |
| v1.6 | 2026-05-25 | **MAC-based identity** — every `/weather` request now carries an `X-Device-Id` header containing the board's MAC address (`WiFi.macAddress()`). Identical units flashed from the same `arduino_secrets.h` are now distinguishable to the hub; the per-device `DEVICE_NAME` becomes an optional initial label that can be renamed in the hub's web UI without reflashing. Paired with server v1.11. |
| v1.5 | 2026-05-24 | **C6 Touch LCD: orientation switching** — QMI8658 accelerometer polled every 250 ms; layout rebuilds between landscape (320×172, two cards side by side) and portrait (172×320, two cards stacked with two-line rain row). Suppressed while lying flat (\|Z\| > 0.85 g) and debounced over a 600 ms stability window. FastIMU library vendored from GitHub tag 1.2.8 since not in the PlatformIO registry. |
| v1.4 | 2026-05-24 | **C6 Touch LCD: touch input** — AXS5106L touch driver vendored under `lib/esp_lcd_touch_axs5106l/`. Any tap anywhere on screen cycles the locale (same as BOOT button). Tap detection via press→release edge in the LVGL indev callback; user callback deferred to next `tick()` with re-entry guard to avoid recursing through the synchronous `showLocale` busy wait. |
| v1.3 | 2026-05-24 | **C6 Touch LCD: LVGL UI** — full migration from TFT_eSPI-style direct drawing to LVGL 8.4 widget tree. Card-based dashboard with amber/blue accent borders, anti-aliased Montserrat fonts (12/14/24/36), themed dark background, modal overlays for boot/connecting/locale/error. Partition table switched to `huge_app.csv` (3 MB app slot). Previous Arduino_GFX-only path replaced; LGFX_config.h shim removed. |
| v1.3-pre | 2026-05-24 | **C6 Touch LCD: display working** — discovered the Touch variant uses completely different pins than the non-Touch LCD-1.47 (BL=23, SCK=1, MOSI=2, RST=22), and that the JD9853 panel needs a custom register init sequence before the backlight will turn on. | v1.2 | 2026-05-15 | **Device naming** — `DEVICE_NAME` added to `arduino_secrets.h`. Sent as `X-Device-Name` HTTP header on every `/weather` request so the hub can display human-readable device names without any server-side config. |
| v1.1 | 2026-05-15 | **Error hold** — display stays on the error screen until the hub reconnects. Previously `g_hasData` stayed `true` on fetch failure, causing stale data to reappear immediately after the error flash. All failure paths now set `g_hasData = false`; `parseWeather()` is the only place that sets it back to `true`. Card timer reset on reconnect. |
| v1.0 | 2026-05-14 | **Initial release** — always-on polling firmware for all four boards. Plain HTTP to the Pi proxy (no TLS, no tokens on device). C6 full dashboard (thermometer graphics, rain dots, indoor/outdoor panels). 3-card OLED cycling for ESP32-CAM, ESP32 DevKit, Uno R4 WiFi. Multi-locale with runtime switching. |
